# Blind review — youtube-to-note (pre-handoff due diligence)

**Reviewed:** `/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note` — all of `src/`, `tests/`, `.github/workflows/ci.yml`, `tsconfig.json`, `jest.config.js`, `package.json`, `extension/`. Verified by reading surrounding code; `npx tsc --noEmit` (clean) and `npx jest` (16 suites / 430 tests, all green) were run during the review.

## Overall verdict

This is a genuinely well-run codebase — clear service boundaries, honest progress reporting, per-request AI parameters instead of mutable provider singletons, real sanitization at every untrusted-input boundary, an atomic and shape-validated disk cache, and CI whose permissions, concurrency, version-agreement and coverage floors actually gate. The core pipeline (`processYouTubeVideo`) is the strongest part: it never throws at its caller, classifies transcript failures by type, and attributes fallback failures per provider. The risk concentrates in two places that on-call will actually be paged for: the **settings tab** (932 lines, zero tests, and it owns credential entry) and the **modal component** (1709 lines, zero tests), where I found a security control that silently does nothing, a provider dropdown that hides a supported provider, and a UI path that can permanently wedge the "one modal at a time" guard. Nothing here is a blocker, and nothing in the note-writing path loses user data — but I'd want findings 1–4 fixed or ticketed before the pager changes hands, and I'd want `settings-tab.ts` under test immediately.

## Findings (most severe first)

**1. HIGH — "Clear Keys" never persists; the credential-removal control is a no-op.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/settings-tab.ts:579-586` calls `this.secureConfig.clearAllApiKeys()`. That lands in `/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/secure-config.ts:402-434`, which only writes `''` into `this.settings` — and the service was constructed over the tab's **copy** (`settings-tab.ts:46` and `:57`, `this.settings = { ...options.plugin.settings }`). No `onSettingsChange`, no `saveSettings`. The handler then calls `this.display()`, which re-copies the untouched plugin settings and repopulates every key field. Net effect: the toast says "Keys cleared", the UI shows them cleared, and `data.json` still holds all five plaintext keys until Obsidian restarts (after which they are fully back). This is the exact control that `warnIfKeysStillOnDisk` (`settings-tab.ts:751-759`) tells users to use to get secrets off disk. Security-relevant and silently broken.

**2. HIGH — the modal's provider dropdown is hardcoded and omits Hugging Face; the `providers` option is dead.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/components/features/youtube/youtube-url-modal.ts:387-393` builds five hardcoded options (Gemini, OpenRouter, Groq, Ollama Cloud, Ollama local). `Hugging Face` is a first-class provider elsewhere (`src/ai/huggingface.ts`, `PROVIDER_MODEL_OPTIONS`, the settings tab) but is unselectable in the UI. Meanwhile `providers?: string[]` (`youtube-url-modal.ts:67`) is populated by `main.ts:374/382` from `aiService.getProviderNames()` and **never read** — a grep for `.providers` finds no consumer. A user with only an HF key gets a dropdown defaulting to "Google Gemini", and `processWith('Google Gemini', …)` throws `Provider "Google Gemini" not found` on every run (`src/services/ai-service.ts:53-56`) before the chain falls forward. It recovers, but the first failure is fabricated, the attribution shows a spurious fallback, and HF can only ever be reached by accident of map order.

**3. MEDIUM — the API-key field is pre-filled with the _masked_ key, and a partial edit commits the mask as the credential.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/settings-tab.ts:296-303` sets `input.value` to `getMaskedApiKey(...)` and on `change` stores `input.value.trim()` verbatim. `change` fires on blur after any edit, so one stray character in the field commits `hf_AbCdEf**…**wXyZ` as the real key. For Gemini/Groq the strict regexes in `APIKeyValidator.PATTERNS` (`secure-config.ts:195-199`) reject the mask, but **Hugging Face, OpenRouter and Ollama have no pattern**, so the only checks are length (20–400) and placeholder words — a masked string of a 30+ char key passes and overwrites the working credential. The run then fails with 401s and nothing tells the user why. `isMasked()` exists at `secure-config.ts:269` precisely to guard this and is **never called** anywhere in `src/` or `tests/`.

**4. MEDIUM — the quota "Retry" button dispatches an event nothing listens for, inside a Notice that never auto-dismisses.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/services/error-handler.ts:54-70` adds a Retry button that fires `window.dispatchEvent(new CustomEvent('yt-clipper-retry-processing'))` — a grep across `src/` finds zero listeners. The Notice is created with duration `0`, i.e. it stays on screen until manually dismissed. Reachable from the most common on-call symptom: `main.ts:666` calls `ErrorHandler.handleEnhanced(enriched, 'AI Processing')` on the aggregate all-providers-failed path, and `isQuotaError` (`error-handler.ts:80-107`) matches on a bare `"429"` or `"rate limit"` in the joined message. So a routine rate-limit failure produces a permanent toast offering a button that does nothing.

**5. MEDIUM — Gemini ignores every part after `parts[0]` and never checks `MAX_TOKENS`, so truncation is silent.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/ai/gemini.ts:229-232` reads only `candidates[0].content.parts[0].text`, and `:90-101` hard-fails unless `parts[0].text` exists. A multi-part text answer silently loses everything after the first part; an answer whose first part is a thought block throws "Invalid response format from Gemini API". Separately, `:86` checks only `finishReason === 'SAFETY'` — a `MAX_TOKENS` finish (likely, given `defaultMaxTokens: 4096` against a 150k-char transcript budget for `complete-transcription`) is returned as a successful, mid-sentence note with no warning, and the deterministic frontmatter/Source blocks make it look finished.

**6. MEDIUM — `window.prompt` throws in Electron, so the clipboard command's manual-entry fallback always fails.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/main.ts:329`. Obsidian desktop is Electron, where `window.prompt()` throws `prompt() is and will not be supported.` Any user running "YouTube Clipper: Open URL Modal (from clipboard)" with a non-YouTube clipboard gets `Error: prompt() is and will not be supported.` instead of the intended input box. The codebase already has the right primitive (`ConfirmationModal`) and even calls it out at `src/components/common/base-modal.ts:160`. Also worth noting: `settings-tab.ts:581` uses `confirm()` for the Clear Keys guard, which the same base-modal comment says is deprecated.

**7. MEDIUM — key migration on load can overwrite a real key with XOR garbage.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/secure-config.ts:295-306`: `isLikelyPlaintextKey` treats any ≥20-char value that `atob()` accepts as legacy-obfuscated. `getApiKey` (`:311-337`) then XOR-decrypts it and accepts the result if it is _not_ valid base64 — which random XOR output almost always is. `migrateApiKeys` (`:344-358`) is called from `loadSettings` (`main.ts:895-898`) and **writes that garbage back to `data.json` and saves**. An opaque Ollama/OpenRouter token that happens to be base64-shaped is therefore silently corrupted on startup, with only an info-level "Migrated legacy obfuscated API keys" in the log. Narrow, but it is silent credential destruction on the load path.

**8. MEDIUM — the single-modal guard can wedge for the rest of the session.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/main.ts:434-438` claims the slot with `beginOpen()` and then calls `modal.open()`. `onOpen` deliberately rethrows (`youtube-url-modal.ts:212-215`), and `onClose` — which is what releases the slot via `onModalClosed` (`:1706`) — only runs if the modal actually closes. Any throw between claim and close (a DOM error in `createModalContent`, a `FORMAT_META` miss) leaves `ModalManager.isModalOpen` true forever; every subsequent ribbon click, command, protocol hand-off and clipboard intake returns "already open — finish or close that one first" until the plugin is disabled/re-enabled or Obsidian restarts. A `try/finally` around the open, or releasing in the `catch` at `main.ts:439-441`, closes the hole.

**9. MEDIUM — the modal's Ctrl+C handler swallows textarea selections.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/components/features/youtube/youtube-url-modal.ts:964-974` intercepts Ctrl+C: if `hasTextSelection()` is false, focus is not the URL input, and a note path exists, it copies the path and `return false` (stops propagation). The guard at `/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/components/features/youtube/youtube-modal-utils.ts:240-243` uses `document.getSelection()`, which in Chromium does **not** report selections inside a `<textarea>`. So after any successful run, selecting text in the "USER INSTRUCTIONS" box and hitting Ctrl+C copies the note path instead — precisely the moment a user is most likely to be copying instructions they wrote.

**10. LOW — the file watcher reads full file contents on every create event and every tab switch.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/services/url-handler.ts:209` (`handleFileCreate`) and `:259` (`handleActiveLeafChange`) both `app.vault.read(file)` before any cheap size/name filter. On a vault that syncs in bulk, or for a user with multi-megabyte notes, every tab switch pays a full file read just to decide "is this a temp clipper note". Reading `stat.size` (already on `file.stat`) before reading content would remove almost all of the cost. The `isTempFile` content heuristic (`:73-92`) also claims any note whose first line is a YouTube URL and that is <5s old, so a note created by another clipper plugin will pop this plugin's modal.

**11. LOW — a cancelled run can still write a note to the vault.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/main.ts:695` calls `assertLive()` once _before_ `saveToFile`, then hands over to `/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/obsidian-file.ts:93-112`, which can block indefinitely on `FileConflictModal` and is not signal-aware. Abort the run while that dialog is up and the pipeline happily writes the note, records it in history, and only afterwards reports "Processing cancelled". Every earlier stage honours the signal; the save stage is the one place it is dropped.

**12. LOW — a user's deliberate "don't save" is reported as an error.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/obsidian-file.ts:106` throws `'Save cancelled by user'`, which `main.ts:723-727` converts into a `❌` Notice and a `success: false` result. The modal's `isCancelledResult` (`youtube-modal-utils.ts:193-197`) only recognises the exact wording "processing cancelled", so the batch UI shows a red failure for what the user chose. Cheap to fix with a second cancellation shape.

**13. LOW — on runtimes without `AbortSignal.timeout`, generation requests are silently unbounded.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/ai/error-utils.ts:45-57`: when only `timeoutMs` is supplied and `AbortSignal.timeout` is missing, `timeoutSignal` is `undefined` and the function returns `undefined` — i.e. **no timeout**, not a fallback timer. The manifest declares `isDesktopOnly: false` (`manifest.json:11`) and `minAppVersion: 0.15.0`, so this is reachable on older mobile builds, and the 60s generation ceiling (`REQUEST_TIMEOUT_MS`) that the comments describe as the guard against a hung provider simply does not exist there. The `AbortSignal.any` fallback two lines below shows the right pattern; the timeout-only branch should get the same treatment.

**14. LOW — the Ollama Cloud API key is sent to whatever `ollamaEndpoint` is configured.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/services/service-container.ts:85-92` constructs the local provider with `ollamaCloudKey || ''`, and `createHeaders` (`src/ai/ollama.ts:275-283`) attaches it as `Authorization: Bearer` unconditionally. Pointing `ollamaEndpoint` at a LAN/remote host therefore exfiltrates the cloud credential in cleartext (there is a `console.warn` for plain-HTTP non-loopback hosts at `ollama.ts:39-49`, but it does not stop the send). It also makes the two settings structurally inseparable: a user who needs auth on _both_ local and cloud Ollama cannot configure both.

**15. LOW — accumulated dead weight worth deleting before it confuses the next owner.**
Verified unused in `src/`: `AIService.setModelParameters` (`src/services/ai-service.ts:198-207`, only referenced by types and a test asserting it is _not_ called), `AIService.process`'s `_images` param and the whole `enableFallback` loop in `processWith` (the pipeline always passes `false`), `SecureKeyStorage`'s localStorage metadata (`src/secure-config.ts:137-188`, written but never read for any decision), `APIKeyValidator.isMasked`, `ErrorHandler.handleQuotaError`/`isQuotaError`/`extractProviderName` (reachable only via the dead button in finding 4), `YouTubeTranscriptService.isTranscriptAvailable`, and `FormatConfig.expectedSections` — six per-format arrays in `src/templates/format-config.ts` consumed only as an existence guard at `src/services/prompt-service.ts:796`; `validateFormatStructure` claims to "check sections" and never does.

**16. LOW — the three most operationally complex files have no direct tests.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/settings-tab.ts` (932 lines, all credential entry/export/import/reset), `/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/components/features/youtube/youtube-url-modal.ts` (1709 lines, the run/batch/retry state machine) and the metadata path of `/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/video-data.ts` (oEmbed + scrape fallback, including the `scrapeAdditionalMetadata` merge) have zero dedicated specs. `jest.config.js:52-56` is candid about this — the `./src/components/` floor is **7%** lines and `src/main.ts` is excluded from coverage entirely, so the floors gate regressions in the tested parts and nothing else. Findings 1, 3, 8 and 9 all live in exactly this gap; the suite is excellent at 430 tests but it is testing the easy 60%.

**17. LOW — prettier is not enforced in CI.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/.github/workflows/ci.yml:40-47` runs lint, type-check and coverage but never `npm run format:check`, even though the script exists and the project's own convention says "indentation is owned by prettier". Formatting is only enforced by the pre-commit `lint-staged` hook, so any commit made with `--no-verify` (or by a tool that skips hooks) lands unformatted and the next `npm run format` produces a diff nobody reviewed.

**18. LOW — history write failures are swallowed, and duplicate detection silently stops working.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/src/services/processing-history.ts:99-112` catches a failed `saveData` and only `logger.warn`s. The user still gets their note, but `find()` (`main.ts:526`) is the duplicate warning, so after one failed write every later run of the same video looks brand new with no signal beyond a console line. A one-line warning in the returned `ProcessingResult.warnings` would surface it where someone can act on it.

**19. LOW — docs drift that will mislead on-call.**
`/home/em/Sync/obs/obs-vault/.obsidian/plugins/youtube-to-note/CLAUDE.md:10` states the plugin is at **2.1.0**; `manifest.json` and `package.json` are both **2.2.0**. ## Areas I checked and consider clean

- **`src/services/transcript-cache.ts`** — the best file in the repo: id-validated paths, segment-sanitized path building, shape-validated reads that treat malformed entries as misses and delete them, unique temp file + atomic rename, bounded at 200 files, every failure logged and non-throwing, and correctly _not_ cleared on unload.
- **`extension/chrome-extension/`** — genuinely zero permissions, content script is top-frame only, all DOM writes via `textContent`/`createElement`/`DOMParser` (never `innerHTML` with page data), canonicalized URL hand-off, and an unusually careful MutationObserver lifecycle (single instance, generation-guarded retry chains, watchdog with an exhaustion flag). No findings.
- **`.github/workflows/ci.yml`** — top-level `contents: read` with only the tag-gated release opting back into write, per-ref concurrency, tag/manifest/package version agreement checked _before_ building, coverage floors that do gate, and a real check that `manifest.json` sits at the ZIP root.
- **`src/services/prompt-service.ts` input handling** — `sanitizeInlineText` flattens control characters and newlines before any remote value reaches a note line, `escapeYamlScalar` uses JSON encoding for frontmatter, `escapeHtmlAttr` guards the iframe, and the modal renders every provider/model/error string through `textContent`. I found no injection path from transcript, metadata, provider or error text into a note or the DOM.
- **`withPluginDataLock`** (`src/services/processing-history.ts:36-51`) — the settings/history read-modify-write interleaving is genuinely serialized, and both writers join the same queue.
- **Cancellation plumbing** — `ProcessingCancelled` + `RequestAbortedError` are threaded consistently from modal close and plugin unload down through `withTimeout`, `fetchGeneration` and the transcript service, and are correctly distinguished from network failures so a cancel is never reported as one.
